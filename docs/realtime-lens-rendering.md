# 实时景深：实现与验证

## 范围与参考

修复样机大师启用景深后旋转卡顿。用户明确拒绝运动时降低采样画质，要求参考本地 UI 相机工作室。未修改 UI 相机、模型素材、存档格式或交互布局。

已阅读并操作本地 UI 相机：`UICameraStudio/src/device.js` 采用 Three.js `RenderPass + BokehPass + OutputPass`；平面图片的 `src/render.js` 使用缓存画布加 CSS 变换。这两种模式都不等于原样机大师每帧 32 次完整场景重绘。

本次使用固定版本 `postprocessing@6.37.8` 的近/远场 Bokeh 处理，并针对样机轮廓与透明输出定制处理。库的 [DepthOfFieldEffect 源码](https://github.com/pmndrs/postprocessing/blob/v6.37.8/src/effects/DepthOfFieldEffect.js) 为参考；依赖采用 Zlib 许可。不是直接复制 UI 相机界面，也不是声称与其原站算法一致。

## 渲染流程

1. 背景独立绘制；每台手机、展台、文字分别绘制颜色和深度，保留原画布 DPR 和最高 4x MSAA。只有一个主体时仍只绘制一次；多个主体共享 Bokeh 中间缓冲，分别保留处理完成的颜色和深度。阴影需要更新时，先用完整场景更新共享阴影。
2. 根据实际视空间深度、焦距、f-number 计算散焦圆；支持透视、弱透视、正交及对数深度。
3. `CoCDilation` 两次最大值扩展使散焦圆的作用范围跨过轮廓，不让半径在背景边界收缩。
4. 在固定半分辨率中间纹理上做近/远场圆形光圈采样，焦内部分始终读取原始全分辨率画面。采样覆盖面积匹配 mipmap 层级，减少细高光边缘的颗粒。
5. 去除库中扩大亮部的最大值填充；合成时移除已离焦的原始轮廓，保留透明覆盖率。通过纹理数组逐像素按深度合成各主体，再补回背景；后方模型被遮住的表面也参与散焦。操作轴单独保持清晰，不参与光圈模糊。
6. 只做一次最终曝光和颜色编码。预览、运动和导出使用同一管线，同分辨率下输出一致；散焦半径随输出尺寸缩放。

不再有运动 4 / 静止 8、预览 32 / 导出 512 的分支，不再按整个 React 状态重置多帧累积。旧 `ThinLensRenderer` 仅留作参考测试，不进入主页面运行时。

## 验证（2026-09-15，本机独立 Chrome）

- 先运行新性能回归的 `--baseline`：原实现完整场景绘制 32 次，测试按预期失败；新实现 1 次。
- Pura FBX、1720×1200 窗口、1.5 DPR、相同 60 次拖动：旧数据中位数 116.7 ms / P95 249.9 ms；当前中位数 16.7 ms / P95 16.8 ms。不是所有机器或模型的帧率承诺。
- 512px GPU 测试：透视近场 f/1 轮廓过渡 22px、f/22 1px；远场分别 11px / 1px。正交近远场 f/1 14px、f/22 1px。对数深度开启和关闭均通过。
- 焦平面像素、播放与静止像素、同尺寸导出与预览像素一致；透明轮廓覆盖率确实扩散。
- 实际页面高 DPI 细纹测试：焦内对比度保留率 100%；收小光圈后离焦区域细节恢复。
- 点选焦点、关键帧、J、Esc、播放时隐藏标记、三种投影、透明 4K PNG 导出通过，无 WebGL 错误。
- 黑色 Pura 边框截图人工检查：离焦轮廓散开、焦内位置保留细节。
- 开启景深时图片与视频背景 MP4 导出通过；红/蓝测试帧分别为 [253,0,0] / [0,0,253]；停末帧、不循环、启动与进行中取消再导出通过。
- 45 项单元测试、TypeScript 检查和离线构建通过。

入口：`node scripts/check-realtime-lens.mjs`、`node --experimental-strip-types scripts/bench-lens-drag.mjs realtime-final`、`node --experimental-strip-types scripts/check-focus.mjs`、`node --experimental-strip-types scripts/check-focus-sharpness.mjs`、`MOCKUP_TEST_LENS=1 node scripts/check-background-export.mjs`。

## 边界与维护

这是基于主体分层的实时景深近似，不是光线追踪或 512 视图物理积分。不同手机之间被遮挡的表面能补回；单台模型内部仍只有一层可见深度，其自遮挡、折叠内侧和多重透射玻璃不是完整物理重建。未标记主体的剩余场景物体合为一层。多个主体增加绘制次数与颜色缓冲显存占用，不能承诺任意数量重型模型均维持 60fps。

固定质量的中间纹理并非“移动时降画质”。不存在静止后才出现另一种景深的等待阶段。依赖内部 Bokeh pass 的定制已集中在 `RealtimeLensRenderer.ts`；升级依赖前必须重跑轮廓、颜色、透明、焦内细节及性能测试。
# 景深等高线修复（2026-09-15）

黑色屏幕上跨越焦平面的平行亮线来自两处：默认 8-bit CoC 纹理把连续模糊半径量化成台阶；远景颜色预乘 CoC 后过滤，再与未过滤的 CoC 相减，合成权重不守恒，导致不透明屏幕局部透出背景。无灯光、无纹理的倾斜平面同样可复现。

CoC 纹理改为 HalfFloat；远景过滤保留原始预乘颜色与真实 alpha，使用同一扩展 CoC 权重对清晰层、模糊层做互补混合。该次修复没有增加场景渲染次数，没有交互降质或关闭景深。当时仍使用整个场景的一层深度；多模型遮挡问题由下面的分层修复处理。

回归：`node scripts/check-lens-banding.mjs`。1024px 倾斜纯色屏幕，f/1、三个焦距位置、白/黑/透明背景；修复前灰度 24 的屏幕出现最高 85 的亮线，修复后保持 24，内部 alpha 为 255。另需执行 `check-realtime-lens.mjs`、`check-focus-sharpness.mjs` 和 `bench-lens-drag.mjs` 检查焦内细节、轮廓虚化及交互性能。

## 前后手机遮挡修复（2026-09-22）

原流程只知道整个场景最前面的一层。将 CoC 扩展过轮廓后，后方手机的虚化会染到清晰前景；对焦后方时，前景轮廓后缺少真实模型内容，只能用画布背景填补。现在 `LensLayers.ts` 按模型/展台/文字分层绘制，光圈过滤每个主体的预乘颜色和覆盖率，按逐像素深度排序合成。纹理数组避免每个模型消耗一个独立纹理采样器，近远 Bokeh 缓冲在各层之间复用。

- `check-lens-overlap.mjs`：焦内红色前景、离焦蓝色后景。修复前前景边缘最大通道误差 182，修复后为 0；对焦后方时，前景边缘没有白画布漏入。透视/正交、普通/对数深度均通过。
- 同一 GPU 测试覆盖三层交叉的逐像素深度顺序、场景插入顺序无关性、透明覆盖率、f/1 与 f/22、播放/导出像素一致、模型可见性恢复。
- `check-lens-multimodel.mjs`：真实两台 Pura FBX 独立屏幕贴图，前后对焦、收小光圈、透明 4K PNG，以及焦点动画 MP4。截图输出在 `/tmp/mockup-layers-*`，不使用或覆盖用户存档。
- 导出回归发现原“4K 渲染图”只截取预览尺寸；改为按画布比例适配 3840×2160 边界，并等待目标分辨率帧就绪再保存，结束后恢复预览 DPR。正方形输出 2160×2160，保留透明背景。
- `bench-lens-drag.mjs overlap-final --two`：1720×1200、DPR 1.5、f/1，拖动真实操作轴使角度从 0° 到 42.97°；60 帧的中位数 16.7ms / P95 16.7ms。本机独立 Chrome 测试，不代表所有设备。单模型继续支持直接拖动旋转，脚本断言模型角度确实改变，避免将静止画面当成旋转性能。
- 焦内高频细节保留率 100%；已有点选焦点、关键帧、三种投影、背景图片/视频导出、取消导出回归通过。58 项单元测试、TypeScript、离线构建通过。

交互不降低光圈质量，不改变存档格式或用户选定的光圈/焦点参数；桌面本地 HTML 继续离线运行。
