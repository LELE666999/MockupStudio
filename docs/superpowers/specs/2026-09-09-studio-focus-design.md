# 棚拍质感与关键帧点选对焦

## 目标与已确认的方向

在现有 3D 样机大师中增加棚拍质感、模型表面点选对焦，以及随关键帧变化的景深。参考 ui.camera 的产品展示方向和 Rotato 的手动对焦交互，不复制其素材或声称达到相同渲染器效果。

保留当前模型、屏幕映射、视频同步、相机投影、连续运动、快捷键、导出与存档流程。不做区域框选系统，不让对焦自动改变相机朝向或构图，不引入路径追踪。

## 用户流程

1. 在环境面板选择「原始 / 棚拍」分段切换。已有项目继续使用原始模式；新建项目默认棚拍模式。
2. 在独立的「镜头与景深」面板打开景深。默认关闭，以免改变旧项目及无意模糊屏幕。
3. 点击「选择焦点」，在任意可见手机模型表面点一下。选中后退出点选模式，显示小焦点标记和所属模型名称；Esc 取消。
4. 调整光圈和虚化上限，再添加关键帧。若播放头位于已有关键帧上，点焦或调整镜头参数会更新该帧的镜头字段，不覆盖该帧其他变换。
5. 在下一个时间点选择其他焦点并保存关键帧。播放时在两个对焦距离之间连续转移，不旋转相机。
6. J/K 跳帧、拖时间轴、保存重开、图片与视频导出使用同一组镜头参数。

没有命中模型的点击不创建焦点，不跳到背景。编辑时标记随模型变换移动，播放、图片导出和视频导出时隐藏。点焦期间暂停动画，禁用旋转、平移、屏幕板块选择与空间快捷键播放，避免一次点击触发两种操作。

## 对焦含义与限制

景深是一台相机对整个场景的深度效果，并非每个模型各自叠一层模糊。每个关键帧可以选择不同模型上的焦点，但同一时刻只有一个有效焦平面。

同一深度的屏幕区域会一起清晰。要突出屏幕上半部而模糊下半部，需要模型有一定倾角；不能用圆形清晰蒙版冒充景深。

透视和弱透视使用相机空间深度。正交也提供按深度虚化，但标明它是景深模拟，不将光圈数值解释为真实镜头的严格物理复刻。虚化强度设上限，避免极端参数造成大面积光晕与失去可读性。

## 数据与焦点绑定

新增可选项目字段 renderStyle（legacy / studio）和 lens 配置；旧文件缺省为 legacy、景深关闭。新项目初始化显式设置 studio，避免旧存档合并初始状态时意外变成新效果。

lens 包含 enabled、aperture、maxBlur、focus。focus 保存 modelId、模型实例根组下的 localPoint 三维坐标，以及选中时的 fallbackWorldPoint。不得保存 Three.js 对象引用、材质、DOM 或临时选择状态。

统一以 ModelInstance 根组为坐标空间：将射线命中的世界坐标转换为根组局部坐标。简单模型与经过居中处理的 FBX/GLB/STL 都使用这一约定，不依赖材质名或嵌套 mesh 的局部原点。运行时维护实例根组注册表，更新矩阵后解析焦点世界坐标。

模型旋转、移动、缩放后焦点自然跟随。模型删除、隐藏或其资源被替换时，焦点退回保存的世界坐标并提示重新选点，不崩溃、不静默绑定到其他手机。

isSelectingFocus 只属于编辑器临时状态，加载与导出后均关闭。存档验证检查字段枚举、数值范围、三维数组及有限数；不合法的新配置应拒绝导入。模型资源与视频仍通过现有内嵌资产机制保存。

## 关键帧与连续焦点

captureFullState 记录 lens；关键帧镜头更新仅写入 lens，不覆写原有 position、rotation、截图等字段。普通编辑保持原有“添加 / 更新关键帧”工作方式，非关键帧时间点不自动制造隐藏关键帧。

每一渲染时刻先得到插值后的模型与相机，再用当前模型矩阵解析相邻关键帧的焦点锚点，计算相机空间正深度。不能用过期的模型位置计算焦距。

逐段模式使用已有 easing/bezier 插值焦距及光圈。连续模式使用共享时间导数的有界单调插值，避免每帧重复起停，并防止焦距插值穿过相机。首尾准确还原关键帧参数。

两端焦点属于不同模型时，分别解析两端锚点，再插值焦距；不在不同模型的局部坐标之间直接插值。两端是同一个锚点时始终跟踪该锚点，允许跟随运动模型自动调整焦距。

对于缺失 lens 的旧关键帧，按该项目的基础镜头设置补全，避免跳帧时随机丢失景深开关。连续平滑、颜色锁定和全局投影模式不被新镜头字段覆盖。

## 棚拍渲染

原始模式保留现有 NoToneMapping 与原始环境表现。棚拍模式引入柔和主光、边缘补光及受控反射环境，采用适合高光压缩的色调映射；不依赖用户联网才能加载的临时 HDR 地址。

使用本地可生成的灯箱环境，避免新增许可不明的素材。优化阴影接触感、玻璃与金属的粗糙度和反射层次。GLB 保留原始 PBR 材质及纹理，不将所有子网格刷成同一金属；新增材质或调整时使用实例副本并释放资源。FBX/STL 没有可靠材质区分时只使用保守默认值，不依据名字猜测摄像头或玻璃结构。

屏幕媒体仍可正常映射、翻转和同步视频；用测试色卡检查棚拍色调映射与自发光，避免泛白、二次 gamma 或视频亮度突然变化。UI 高亮材质、编辑器辅助物不参与最终画面。

## 景深渲染管线与性能

以深度纹理驱动实时后处理，实现焦点前后不同程度的虚化；不使用 CSS filter 或整屏高斯模糊替代景深。

后处理独立为场景组件，统一管理颜色、深度、虚化与最终合成。关闭景深时不运行额外景深 pass。根据当前已安装 Three.js 版本验证实现路径与兼容性后再引入必要依赖，不盲目升级 React/Three。

预览采用受控分辨率与采样预算，导出提高质量；两者保持同一焦点、光圈和归一化虚化大小，不能因为导出分辨率变化而虚化扩大数倍。尺寸、DPR、投影改变时重建或调整 render targets 并释放旧资源。

保留透明背景 alpha，测试手机边缘、屏幕、玻璃和阴影处的合成；不将透明区渲染成黑色底。无法可靠支持的硬件或 framebuffer 配置要给出提示并回退到清晰渲染，不让整个画布消失。

现有 always 渲染与 UI 状态更新需测量帧耗时后再局部优化，不在此任务重写整个状态管理。焦点计算避免每帧 React setState，优先通过稳定引用更新后处理参数。

## 导出与可靠性

当前视频导出在时间更新、视频 seek 后等待两次 rAF；新管线应增加明确的“该时间的最终景深画面已完成”就绪确认，再构造 VideoFrame，避免把上一帧焦点导出。

图片导出同样读取最终合成结果，不绕过景深。停止或取消导出时释放等待者、恢复预览质量及编辑器可见性。视频维持现有 60 fps 整数帧序号和正常 1 倍速，不增加独立视频时钟。

保留 Ctrl/⌘S 的版本冲突保护与草稿队列，不把镜头临时状态或较旧异步快照写回新草稿。依赖升级和生产构建成功后才更新桌面可用版本。

## 验收

- 数学测试：倾斜/旋转/平移/缩放后的局部焦点仍对应同一表面位置；同深度焦点一致；弱透视实际相机距离正确；正交深度计算不依赖 fov。
- 动画测试：关键帧端点精确、连续模式焦距无非预期停顿、跨模型转焦无坐标跳变、参数有界、旧关键帧可用。
- 存档测试：完整项目重开后焦点、光圈、渲染模式一致，旧项目外观模式保持原值，非法 lens 不导入。
- 浏览器测试：简单模型与至少一个导入模型都可点焦，点击空白不改焦点，Esc 取消，点焦不误旋转/选择屏幕，播放与导出无标记。
- 视觉验收：棚拍与原始模式使用相同姿态与贴图对比；斜放手机点近处/远处时清晰区域变化；小光圈比大光圈更清晰；屏幕色卡、透明边缘、视频画面无明显退化。
- 导出测试：至少一段含视频贴图、相机运动、两个焦点和光圈变化的短片，核对帧数、焦点时序、alpha 图片、导出取消后恢复。
- 性能验收：同一窗口与模型记录关闭/开启景深的帧耗时，检查反复切换模式后资源数量稳定。只报告实测结果，不承诺所有设备固定 60 fps。

## 不在本轮范围

完整光线追踪、自动运镜构图、区域序列重新设计、自动识别导入模型每个零件的物理材质、多焦平面合成、运动模糊，以及重做现有页面布局。
